# Source-to-sink and manual security review

## Status aliases

Source: authenticated session and tenant context. Boundary: production tenant
authentication followed by the existing current scheduling-operator directory.
Sink: JSON operational metadata. Unauthorized active employees never reach the
count query and receive no stored/customer/worker fields. Authorized counts use
the request tenant ID as a parameterized PostgreSQL value. No response body is
interpolated into HTML.

## Overview cursor

Source: untrusted `req.query.cursor`, including Express arrays. Boundary: strict
type/length/alphabet, decode/re-encode equality, exact JSON schema and spelling,
lowercase UUID, exact microsecond UTC form, and calendar validation. The
Command Center route rejects before pool resolution; the repository independently
rejects before connection. Sink: two parameterized keyset values in the existing
tenant-scoped ordered query. No cursor text enters SQL syntax, logs, HTML, or an
error echo.

## Daily Brief layout

Source: existing safely rendered headings and tenant-time text. Boundary/sink:
CSS reflow only. No HTML renderer or customer-content source changed. Existing
hostile-byte browser fixtures remain inert and browser matrices report no page
errors or external calls.

## Separate reviewer pass

A post-test security review traced alternate canonical graph, dashboard,
analytics, surface, compatibility, and Command Center routes. All cursor-bearing
canonical aliases parse before broad-data lookup; the overview route and
repository both reject before a scan. Both status aliases share the same safe
builder. No alternate completed-graph count route, direct browser PATCH, provider
call, mutation authority, migration change, or new capability system was added.
The optional scanner was deliberately not invoked because its required config is
unavailable.
