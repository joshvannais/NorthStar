# Mission 26 Part 11C — saved-run currentness prerequisite

Status: unmounted, pure projection only. No saved forecast run, current advice endpoint, automatic propagation worker, or final Part 11C acceptance exists.

`forecastRunCurrentness` takes a Part 11B receipt and **supplied** current-source and algorithm decisions. The source decision binds to the receipt's captured source digest. A `current` claim requires the same current digest; a `changed` claim requires a different digest. An active algorithm claim must match the run's key, version and definition/implementation digests. A replacement must use a different key or version; changed digests under the same immutable key/version are invalid. A correction or algorithm replacement marks the whole run `stale`. Revocation, deletion, expired retention, withdrawn algorithm or unknown status makes it `unavailable` and masks the run identity in the returned projection. Only unchanged supplied pins produce `unchanged_candidate`, which is deliberately not permission to display advice. The result contains no forecast amount or source value and leaves the original immutable receipt intact.

This conservative run-wide treatment is necessary because the Part 11B receipt has one source snapshot and feature-set digest but no accepted per-output dependency map. A future mounted ledger could invalidate only affected targets after it persists and verifies their exact dependency edges; until then, a changed source must not leave an unrelated-looking point presented as current without proof. A corrected source calls for a new authorized snapshot and a newly issued run. It does not edit the historical run or silently restore advice. An algorithm version change likewise cannot rewrite an earlier output or claim a calibrated rerun under changed inputs.

The pure function cannot authenticate a caller-supplied correction, revocation, deletion, retention state, algorithm catalog entry or run receipt. It must never be mounted directly on user-provided flags. The eventual reader must load the immutable run and current source/algorithm authority server-side, recheck tenant, owner/administrator, purpose, record scope and retention on every read, and fail closed if any dependency cannot be checked. Revocation/deletion must mask derived display data and may require lawful removal of retained details; a non-sensitive receipt survives only where retention policy permits. Historical access, when allowed, must visibly label superseded or stale outputs and cannot silently revive current advice.

The mounted Part 11C path also needs durable bounded dependency indexing, idempotent correction events, restart/recovery, concurrent read and event ordering, cache/export invalidation, alert withdrawal, and propagation to displayed cards, charts, drilldowns and advice. Part 10D exports must carry point-in-time validity, and Part 11D recommendations remain reviewed handoffs. The source-specific Mission 24 currentness reader is the only accepted source today; other Mission 25/import/provider sources need their own authorized lifecycle readers before registration. Algorithm retirement/version authority and an immutable PostgreSQL run ledger are still missing.

Focused tests cover changed, revoked, deleted, expired and unknown source states; replaced, withdrawn and unknown algorithm states; exact digest matching; malformed inputs; deterministic frozen projections; and withholding output detail. Final acceptance requires real saved-run and source/algorithm authority, adversarial cross-tenant and role checks, correction/deletion/retention behavior, bounded recovery across restart, paid/demo isolation, rendered plain-language invalidation and independent exact-head review. No CI, provider, private-production, physical-device or founder visual evidence is implied.
