# Mission 26 Part 9E - forecast evidence experience

The shared paid/demo Command Center contains one compact Forecast ranges surface beside the existing Demand and Resource outlooks. It consumes the released Part 9A deterministic-baseline, Part 9B calibrated-range assessment and Part 9C named-scenario contracts. A Part 9D sensitivity result can enter the renderer only after it validates against the exact current Part 9C review, source, assumptions and currentness digests. The browser does not calculate forecast values, combine identities or start a sensitivity analysis without an explicit target from its authorized workflow.

The four cards deliberately keep different meanings separate:

- **Point baseline** reports whether one exact authenticated origin has a current deterministic research result. Its numeric value remains withheld because Part 9A disables paid numeric serving.
- **Calibrated range** displays `P10 / P50 / P90 withheld`. Released Part 9B has no qualifying held-out calibration evidence and issues no distribution, percentile or empirical coverage claim.
- **Named scenarios** identifies current reviewed adverse/base/favorable assumptions as what-if variations. It never presents them as percentiles, measured odds or alternative historical facts.
- **Sensitivity** distinguishes a bounded forward/reverse what-if from an impossible target. An impossible result names the binding constraint without inventing a weight; supported numeric results remain withheld because Part 9D disables paid numeric serving.

Every accepted response retains its exact target, origin/source snapshot, estimate or scenario revision, algorithm/build/configuration, horizon/grain, unit/currency, business time zone, issue/evaluation/currentness, reason and digest evidence in the expandable review area. Incompatible, partial or malformed responses fail closed per card. Authenticated zero remains a value in the guarded contract and is never replaced by an unavailable state; because paid numeric serving is disabled, neither zero nor a nonzero amount is rendered.

Loading and workspace loss clear every previous value, evidence row, digest, explanation and evidence-map state before another response can render. Generation checks prevent late responses from restoring stale data after correction, revocation, status/revision change, reset, expiry or recovery. A paid failure stays unavailable and never falls back to demo data.

Demo uses the same renderer with isolated fictional value-free inputs. It makes no paid forecast request and explicitly says the example is fictional. It does not imply provider, customer, probability, calibration or revenue confirmation.

The evidence map is qualitative and declares that it has no shared quantitative scale. The surface keeps keyboard focus on its native details control, exposes polite atomic status updates, uses the existing responsive shell and theme variables, and remains a single Command Center experience rather than a separate dashboard.

Automated acceptance covers exact-contract rejection, fabricated P10/calibration claims, zero-versus-unavailable presentation, tenant/role/mode isolation, scenario-to-sensitivity identity binding, impossible constraints, correction and failure recovery, stale clearing, demo reset/expiry behavior, keyboard/focus semantics, status and evidence-map accessibility, reduced motion, responsive overflow and light/dark presentation. Chrome and Playwright WebKit each exercise paid/demo at mobile/desktop sizes in both themes. These checks do not establish live provider behavior, private-production evidence, physical Safari behavior or founder visual approval.
