# Mission 26 Part 10C — supplied forecast drilldown prerequisite

The unmounted `forecastDrilldownPosition` reuses Part 10A's bounded timeline and the existing output contract to expose an inspectable **caller-supplied** source-coverage count, stale-input count, uncertainty-driver tokens, confidence state, and immutable output/snapshot digests for each visible current period. It does not authenticate a source, establish complete run inventory or claim that a supplied confidence state is calibrated. Structured assumptions remain explicitly unavailable because no assumption-lineage contract is supplied.

For two comparable point forecasts it calculates the signed current-minus-prior change with exact six-decimal arithmetic. The cause of the change remains unknown rather than being invented from the delta. Where Part 10A has a matching supplied known outcome, it calculates signed current-forecast-minus-outcome error; the outcome's source finality remains unproved. Missing prior runs, outcomes, point values, or calendar normalization withhold the affected comparison and never become zero. Range values are not quietly reduced to their central point for an error claim. The projector rejects a changed output whose digest no longer matches its supplied run receipt, and retains Part 10A's tenant/target/unit/window constraints.

This is a drilldown-data prerequisite, **not** a paid/demo UI or final Part 10C acceptance. No route, migration, graph, live source read, reviewed assumptions, explanation of cause, calibrated probability or issued forecast is added. `sourceAuthenticated`, `runInventoryComplete`, `actualSourceAuthenticated` and `forecastIssued` remain false. Part 11's future source-authorized run inventory, correction invalidation and outcome readers must authenticate the receipts before a customer or owner sees a numerical drilldown. Part 10B's same-run gate and Part 3C's evaluation gate must also apply. Until then, the Command Center should explain that the forecast and its supporting detail are unavailable.

The focused synthetic tests cover the signed change and error, missing evidence, changed calendar, output tampering and tenant mismatch. Final acceptance still needs source-authenticated assumptions, meaningful confidence/calibration, stale and corrected input detection, actual outcome authority, accurate attribution of *why* a value changed, paid/demo desktop/mobile drilldown and recovery, privacy/role checks, and independent exact-head review. CI, provider, private-production and physical-device evidence must be stated separately.
