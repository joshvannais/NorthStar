## Authority rule

Mission 26 may produce separate, tenant-private, advisory forecast records from authorized **as-of** snapshots. It does not edit a source fact, approved estimate, price, schedule, dispatch, job, learning proposal, invoice, payment, policy or customer record. An existing row, source schema, or Learning Center suggestion is not evidence that a tenant has enough current, comparable history for a forecast. Per-tenant readiness must be measured before each target is enabled. Part 2A still must create immutable as-of snapshots; Parts 1B-C must define output and isolation contracts before a runtime forecast is adopted.

## Current forecast-named code is not Mission 26 authority

The unlisted investor artifact at `src/routes/investorForecast.js` and `public/unlisted/investor-forecast.html` has separate investor purpose. `src/polaris/analytics-engine.js` also exposes a `Company Forecast`, but its optional `financial-engine` import is absent in this repository and it combines a fallback revenue result with `src/polaris/opportunity-engine.js`'s fixed stage probabilities. That opportunity engine stores an in-memory opportunity map and defines favorable/most-likely/adverse-style values from simple multipliers, not as-of tenant evidence or backtested intervals. `src/analytics/revenue.js` estimates lead values from hardcoded service ranges and a default average. Existing Command Center labels that say “forecast” do not confer Mission 26 lineage, calibration or financial authority. These paths require separate audit and an explicit compatibility decision before any reuse; they must not seed a canonical Mission 26 run or silently supply missing values.

## Readiness decision for each future target

Before forecast computation, a target-specific reader must prove: (1) current tenant and role authority; (2) source owner and exact consent/purpose where required; (3) an as-of snapshot with no later correction or outcome leakage; (4) sufficient comparable observation windows for that target, service, area and horizon; (5) exact units, currency and time-zone normalization; (6) resolution of duplicates, reviewed relationships and scope changes; (7) explicit missing, stale, contradictory and inapplicable values; and (8) outcome windows and backtest eligibility. Failure yields a bounded unavailable or narrower result with a reason, never zero, a borrowed tenant sample, a hardcoded industry price, or invented confidence.

Part 1A inventories these dependencies only. Part 1B defines the output contract; Part 1C defines privacy and audit boundaries; Parts 2-3 must prove as-of lineage and calibration. Forecast families in Parts 4-9 remain future implementation, not current capability. Native cash and collections wait for Mission 27. Mission 32 may later consume a reviewed forecast in its owner/estimator workspace, but it owns execution planning and never inherits authority to turn a prediction into an approved estimate.
