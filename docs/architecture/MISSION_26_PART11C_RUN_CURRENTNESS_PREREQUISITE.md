# Mission 26 Part 11C — saved-run currentness prerequisite

Status: mounted implementation candidate on the Part 11C branch; independent exact-head audit, merge, migration 256 deployment and release health verification remain pending. No automatic propagation worker or final Part 11C acceptance is claimed.

`forecastRunCurrentness` takes a Part 11B receipt and **supplied** current-source and algorithm decisions. The source decision binds to the receipt's captured source digest. A `current` claim requires the same current digest; a `changed` claim requires a different digest. An active algorithm claim must match the run's key, version and definition/implementation digests. A replacement must use a different key or version; changed digests under the same immutable key/version are invalid. A correction or algorithm replacement marks the whole run `stale`. Revocation, deletion, expired retention, withdrawn algorithm or unknown status makes it `unavailable` and masks the run identity in the returned projection. Only unchanged supplied pins produce `unchanged_candidate`, which is deliberately not permission to display advice. The result contains no forecast amount or source value and leaves the original immutable receipt intact.

This conservative run-wide treatment is necessary because the Part 11B receipt has one source snapshot and feature-set digest but no accepted per-output dependency map. A future mounted ledger could invalidate only affected targets after it persists and verifies their exact dependency edges; until then, a changed source must not leave an unrelated-looking point presented as current without proof. A corrected source calls for a new authorized snapshot and a newly issued run. It does not edit the historical run or silently restore advice. An algorithm version change likewise cannot rewrite an earlier output or claim a calibrated rerun under changed inputs.

The pure function cannot authenticate a caller-supplied correction, revocation, deletion, retention state, algorithm catalog entry or run receipt and is not mounted on user-provided flags. Migration 256 instead records one immutable run-wide dependency index per Part 11B run and exposes a paid owner/admin currentness reader that resolves tenant and actor from the authenticated session, reloads the immutable run and current settings, validates the exact registered algorithm and installed calculator build, and appends only changed currentness decisions under a bounded per-run lock. Runtime access is limited to security-definer entry points; dependency rows, event rows, the raw Part 11B reader and raw comparison/rerun functions remain withheld. Revocation/deletion must mask derived display data and may require lawful removal of retained details; a non-sensitive receipt survives only where retention policy permits. Historical access, when allowed, must visibly label superseded or stale outputs and cannot silently revive current advice.

The mounted candidate now has durable bounded dependency indexing, predecessor-linked immutable currentness events, deterministic concurrent reads, restart-safe PostgreSQL state and one fail-closed browser gate ahead of the existing paid Part 10 ranges, cards, timelines, KPIs, drilldowns, alerts, advice and exports. The gate clears cached and rendered forecast state before those controllers can load whenever currentness is not an unchanged candidate. Demo remains isolated and fictional and does not call the paid currentness route. Part 10D exports retain their point-in-time labels, and Part 11D recommendations remain reviewed handoffs.

The source-specific Mission 24 reader remains the only accepted lifecycle authority. Released Part 11B receipts currently pin Retell future origins, and no authenticated Retell correction/revocation/deletion/retention reader or compatible Mission 24-backed Part 11B run exists. Migration 256 therefore returns the named, value-free `unsupported_source_currentness` state, masks run identity and derived values, and records the missing source proof without treating it as zero. It does not manufacture a source adapter, current advice, correction event or restored value. The exact algorithm catalog and installed build are still checked independently; missing, withdrawn or digest-mismatched algorithm evidence is recorded as unknown even while the unsupported source remains the primary unavailable reason.

Focused pure tests cover changed, revoked, deleted, expired and unknown source states; replaced, withdrawn and unknown algorithm states; exact digest matching; malformed inputs; deterministic frozen projections; and withholding output detail. Mounted tests cover immutable saved runs, unsupported-source masking, exact algorithm/build tamper and recovery events, idempotent and concurrent reads, bounded lock recovery, cross-tenant/role/runtime isolation, retained history, paid/demo lifecycle clearing and Chrome/Playwright WebKit rendering. Authenticated Mission 24-backed saved runs, a Retell lifecycle adapter, natural provider correction/deletion/retention history, CI, private production, physical devices and founder visual approval remain unavailable. Final acceptance remains open until independent exact-head review and release verification.
