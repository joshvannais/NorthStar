# Mission 26 Part 10C — authenticated forecast drilldown boundary

Part 10C mounts `GET /api/v1/forecast/drilldowns/:originId` beside the released Part 10A timeline and Part 10B monthly KPI boundaries. The route is tenant- and role-guarded and projects only an exact, current Part 10B bundle. Its six ordered drilldown slots retain the same tenant, run, target, unit, scope, month, cutoff, calendar, algorithm, source, output and currentness identities as the corresponding KPI slots. The server and browser reject reordered, mixed, changed or extra slot identities rather than combining detail from incompatible evidence.

The deployed repository does not yet contain the Part 11-owned authenticated multi-target run manifest, assumption lineage, correction lifecycle or finalized outcome readers needed to support numerical drilldown claims. The mounted boundary therefore reports value-free unavailable source coverage, assumptions, confidence, uncertainty, stale-input detail, point change and forecast error. Cause is explicitly unknown. It never treats an unknown numerator or denominator as zero, labels a narrative as an assumption, invents a confidence percentage, reduces a range or scenario to a point, attributes cause from a numerical delta, or compares a prediction issued after its outcome.

Currentness changes fail closed. Loading, permission loss, correction, revocation, deletion, reset, expiry and recovery clear all prior counts, causes, errors, digests and explanations before another response can render. A current compatible bundle preserves its authenticated identities without creating a new digest. A stale or unavailable bundle carries no period, anchor or bundle digest. This keeps complete authenticated zero distinct from absent or unavailable evidence.

Demo mode creates only isolated fictional unavailable detail and does not call paid forecast routes.
