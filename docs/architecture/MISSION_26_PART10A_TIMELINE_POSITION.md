# Mission 26 Part 10A — supplied forecast timeline prerequisite

The unmounted `forecastTimelinePosition` projects supplied Part 3B comparison receipts into weekly, monthly or quarterly periods. It retains the latest and immediately preceding **supplied** prediction origins for a horizon, each with run identity, as-of time, immutable output digest and point or range value. An actual appears only when both compared runs have matching finalized outcome amount, source digest and cutoff. Missing prior history, an unmatched actual, or duplicate prediction origins remain unavailable; no gap becomes zero. It reuses Part 3B's tenant, target, unit, applicability, algorithm and reporting-window validation rather than creating a separate forecast ledger.

This is a display-data prerequisite, **not** a live current-versus-prior-versus-actual Command Center timeline or final Part 10A acceptance. Its run and outcome arrays are caller supplied; it cannot prove that the latest run or complete inventory was provided, authenticate actuals, establish current corrections/permissions, or issue a forecast. `sourceAuthenticated`, `runInventoryComplete`, `actualSourceAuthenticated` and `forecastIssued` remain false. No route, migration, chart or numeric paid/demo UI is added.

A future guarded Part 11 saved-run reader must select tenant-authorized immutable runs and their current revision lineage, determine the complete applicable inventory, and verify later outcome receipts from the owning source. Part 10A can then present time-aligned prior/current/actual values while distinguishing prediction from fact and withholding incomparable windows. Synthetic tests cover all three grains, order-independent projection, missing prior, conflicting actual, duplicate origins, unsupported grain and tenant mismatch; these are not production source evidence.
