# Mission 28 Part 5D — collision, suppression and no-effect analysis

Part 5D freezes a deterministic source contract for collision and suppression analysis. It does not mount a resolver, store, route, UI, scheduler, queue, worker, provider, recipient or effect executor. A selected candidate is only counterfactual analysis evidence; it is never eligibility, approval, scheduling, claim or effect authority.

## Exact inputs

One analysis binds a separately trusted tenant, server-issued analysis identity, mode, clock, bounded window, ordered candidate set and the complete ordered control set for every candidate. A server-owned tenant-private resolver independent of candidate input must supply that material. Each candidate binds the exact accepted eligible Part 5B output, Part 5C preview, policy, rule/template, authorization, source set, internal recipient set, provider-disabled channel, no-effect material, priority and collision scope. Candidate content is represented only by a canonical digest. No customer, message, document or provider body is accepted, and a candidate or recomputed digest cannot self-attest any resolution.

The eleven controls are closed and ordered: global, tenant, customer and document pauses; recipient opt-out; provider uncertainty; source change; active conversation; recent manual activity; duplicate content; and an already-active higher-priority action. Every kind has a distinct canonical scope digest: global, tenant, customer, document, recipient, provider-mode, source-set, conversation, manual-activity, content, and collision scopes cannot substitute for one another. Applicable clear or matched controls require exact tenant-private accepted evidence observed and accepted no later than the trusted analysis time. Missing, stale, mixed, ambiguous, future, unaccepted or mismatched evidence is represented as unavailable with no fabricated evidence identity, never clear. Customer, document, opt-out and conversation controls may be not applicable only when the exact candidate scope proves that condition.

## Deterministic precedence

Unavailable evidence, source changes and provider uncertainty fail closed first. Global, tenant, customer and document pauses then suppress, followed by opt-out, active conversation, recent manual activity and duplicate content. An already-active higher-priority action supersedes the candidate. Only candidates clear through those controls enter overlap arbitration.

Within one exact collision scope, a unique lowest positive priority rank is selected with no effect and lower-priority candidates are superseded. Two equal highest-priority candidates make the entire otherwise-clear scope unavailable; input order and identifiers never break the tie. Every decision contains one winning closed reason and only its exact evidence or dominant-candidate reference.

## Dry run and historical backtest

Dry run consumes exact current accepted tenant-private evidence. Historical backtest consumes only evidence that was accepted at or before its trusted historical time; later evidence is not allowed to leak backward. Both modes return zero effects, `not_provider_proof` and `not_outcome_proof`. They cannot be presented as delivery, response, provider, customer or business-outcome evidence and cannot be replayed as current authority.
