# Mission 26 Part 6A: booked-confirmation source anchor

An authorized paid owner or administrator can start a tenant-private, append-only observation boundary for NorthStar booked-work confirmations. The capture requires current write authority, CSRF, an idempotency key, a reason and explicit confirmation. It takes the same tenant commercial lock used by confirmation writers, waits for earlier source transactions and holds the lock until its own commit. The first capture wins; an exact replay returns the same anchor. No old booking is backfilled.

The guarded source-month read permits a positive observed amount only when the entire requested UTC month starts after the anchor and has ended. It then checks every bounded current confirmation for that month through the existing per-job currentness reader. The result identifies a NorthStar confirmation-source month and the current confirmed cohort; it **does not reconstruct the month-end booked balance**, prove that the job was first booked in that month, or verify off-platform/whole-business coverage. An absent anchor, open or earlier month, stale confirmation, empty cohort, mixed currency or oversized cohort returns unavailable without an amount. `completePeriodVerified` stays false because all commercially relevant sources and month-end state are not yet proven.

The focused mounted fictional-tenant test covers capture authority, replay, private table access, missing/open-month unavailability and a rolled-back synthetic closed-month positive path. The shifted dates in that test create no durable history or live validation. Cross-source contention, complete commercial period authority, paid/demo frontend wording, release and full Part 6A acceptance remain open.
