# Mission 26 Part 9A — deterministic baseline forecasts

Part 9A mounts a guarded, research-only reader for the deterministic inbound-demand baseline already calculated and saved by the source-authenticated Part 4A Retell origin. The reader does not recalculate the mean or introduce another forecast engine. It authenticates the origin against current tenant ownership, subscription, role, provider ownership, business profile, time zone, calendar, source certificates, and current complete-as-of evidence before returning the saved value.

`GET /api/v1/forecast/deterministic-baselines/:originId` is limited to an onboarded owner or admin with forecast read authority. Its result identifies one exact fixed configuration and one exact immutable source snapshot. The response preserves the target and Retell-only scope, algorithm identity and version, immutable definition digest, installed PostgreSQL function-definition build identity and implementation digest, profile revision and digest, business time zone and calendar, future horizon, unit, ordered observation months and values, certificate and snapshot lineage, pagination and coverage, source and evaluation timestamps, currentness, and separate configuration, input, output, baseline, and receipt digests. The algorithm registry is immutable and the reader recomputes both its definition identity and installed function digest before releasing a value.

The baseline digest is independent of the origin identifier and request time. The same authenticated configuration and normalized observations therefore produce the same digest. Observation order is normalized. A source, profile, period, certificate, correction, revocation, configuration, definition, implementation, or build change changes the relevant identity or makes the saved origin unavailable. The chronology fence requires `issuedAt <= checkedAt < horizon.startsAt`; clock rollback and reads at or after the horizon withdraw every issued value and digest. Other stale and unavailable responses likewise clear the source snapshot, output, provenance, and all issued digests so an older value cannot remain visible. A complete observed and forecast value of zero remains an issued zero, distinct from absence.

The endpoint is deliberately outside paid numeric serving and has no user-interface mount. It issues no probability, quantiles, calibrated range, scenario, sensitivity result, recommendation, or operational action. Evaluation remains explicitly unavailable because no compatible finalized outcome has been joined. The returned source-receipt digest authenticates the reused Part 4A origin; Part 9A does not persist another run or claim the general immutable run storage owned by Part 11.

Mounted PostgreSQL integration coverage applies the full production migration chain to a disposable database and verifies reproducibility, complete zero, tenant and role isolation, direct-table and helper denial, revocation, stale-value clearing, correction recovery, and digest changes. Focused unit coverage verifies strict response validation, input-order normalization, configuration and source changes, unavailable propagation, and route transaction behavior. Real provider and private-production evidence, physical Safari, CI, and founder visual approval remain outside this slice.
