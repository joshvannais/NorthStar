## First runtime adoption criteria

The first runtime package should choose one narrow, already released, outcome-bearing source set with an exact business decision it can improve. It must include both its estimate/baseline side and actual/outcome side, current purpose consent, immutable observation lineage, correction/tombstone propagation, a deterministic advisory comparison and a human adoption boundary. It must not begin with a generic score, opaque model, dashboard-only mockup or cross-tenant corpus.

## Released labor-duration contract

Migration `083_canonical_labor_outcome_learning.sql` and `/api/v1/learning` implement that first narrow adoption. The baseline is the current adopted Mission 24 labor plan. The outcome is the complete set of current Mission 23 labor intervals for the linked completed execution; every non-break interval must be accepted, and breaks are retained in lineage but excluded from worker-hour totals. `canonical_labor_outcome_observations.source_manifest` pins every source identity, revision and digest used by algorithm `labor_duration_variance_v1`.

The comparison reports planned worker hours, recorded worker hours excluding breaks, absolute and percentage variance, and one deterministic advisory band. It is available only to current owners and administrators with active consent, and each observation retains an explicit confirmation and confirmation-contract version. A later source correction changes the live source digest and makes earlier advice unavailable until a new observation revision is recorded. Consent revocation prevents observation and suppresses derived history from runtime reads. A later re-grant can produce a new consent-bound observation from otherwise unchanged sources. No result is automatically adopted by estimating, scheduling, workforce or business-profile authority.

## Released external-labor import contract

Migration `084_canonical_external_labor_import_authority.sql` accepts only schema `m25-external-labor-time-v1`. A source is a tenant-owned opaque key rather than a vendor name baked into the schema. Historical pages and continuous updates use separate cursor chains. Batches contain at most 100 normalized records and preserve source record identity, version, source update time, work interval, category, opaque worker/job references, consent and immutable run lineage. Exact duplicate versions are counted without creating another record. A same-version payload conflict or older version fails closed. A newer version creates an immutable correction; a tombstone creates a detail-free current record.

The current projection is available only while that source's consent is active. It masks tombstoned work details and labels the records as staged evidence. No current record becomes a Mission 23 labor interval and no labor-duration advisory consumes it. Reviewed worker/job matching, retention/deletion execution, provider credentials, CSV/browser experience and source-specific adapters remain later work.

## Released external-labor reconciliation contract

Migration `085_canonical_external_labor_reconciliation.sql` provides reviewed worker and job reference reconciliation by recording explicit owner or administrator links from current external worker and job references to current same-tenant workforce profiles and estimates. The current imported-record manifest and target basis are digested independently. Corrections, tombstones, profile changes and membership status changes therefore make a prior link stale instead of silently changing its meaning. Consent revocation hides the projection and blocks writes. These links are advisory lineage only; no imported record is yet eligible for an outcome observation.

## Released imported labor-duration outcome contract

Migration `086_canonical_imported_labor_outcomes.sql` makes current matched external labor records eligible for one narrow planned-versus-recorded worker-hour comparison. The business must grant a separate purpose consent while source consent is current. The job match must point to the estimate and every current worker reference must have a current match. The immutable observation pins all source records and reviewed links. It reports a deterministic variance advisory and never adopts a changed rate, plan, price, schedule or policy.

## Released multi-job imported labor calibration contract

Migration `087_canonical_imported_labor_calibration.sql` adds separately consented, tenant-private multi-job imported labor calibration proposals. Five to 100 current reviewed estimate-and-external-job outcome chains for one normalized service key form a pinned sample. Freshness precedes the sample cap, and candidate evaluation fails closed beyond a documented 10,000-chain bound. The deterministic median and quartiles describe recorded-to-planned worker-hour ratios, while a fixed five-percent band produces an advisory only. Corrections or consent changes stale the proposal and mask its recommendation; delayed exact-key retries retain that masking. No operational authority is mutated.

## Released Owner Learning Center projection

The paid interface composes existing guarded source-detail, consent, reference-match and calibration reads and mutations; it does not select protected tables or copy their data into a parallel browser authority. The demo uses explicit read-only fictional records. Every calibration remains advisory and every operational adoption remains outside this interface.

## Part 9 Slice A — normalized travel evidence

## Released Part 9 Slice C — imported travel outcomes

Migration `092_canonical_imported_travel_outcomes.sql` adds separate purpose consent and immutable observations for an exact adopted travel plan and the current reviewed imported records for one job. Every current vehicle reference and the job reference must retain a current owner-reviewed match. Duration, distance, fuel or energy quantity and fuel cost are compared independently. Miles, US gallons and kilowatt-hours retain explicit units; currency must match exactly. Missing data, straight-line geometry, incompatible energy classes and mixed or incomplete currencies remain unavailable. The observation pins the estimate, revision, travel plan, source consent, job match, vehicle matches and every current imported record. It is advisory and cannot alter operational or pricing authority.

## Released Part 9 Slice D — multi-job imported travel calibration

Migration `093_canonical_imported_travel_calibration.sql` adds separate calibration consent and immutable proposals for one exact normalized service key. Five to 100 current reviewed imported travel outcome chains form the pinned sample after freshness evaluation. Route duration, distance, fuel or energy quantity and fuel cost are summarized independently with deterministic median and lower and upper quartile actual-to-planned ratios. A dimension needs five compatible observations with one exact unit or currency. Incompatible dimensions remain unavailable without suppressing valid dimensions.

The median becomes an advisory multiplier and fixed five-percent bands describe whether the current assumption may be kept, increased or decreased. Source corrections, reviewed-match changes, adopted-plan changes, observation refreshes and consent changes make saved advice stale and mask the multiplier. Exact delayed request replay remains immutable. No estimate, travel plan, route, schedule, reimbursement, payroll record, asset, price or business policy is changed.

## Released Part 9 Slice E — travel-source operations

Migration `094_canonical_external_travel_import_operations.sql` adds immutable travel-source adapter, retention, deletion and cleanup-run lineage. Historical backfill and continuous-update checkpoints remain independent and visible through the guarded operations projection. Provider-neutral adapter state stores connection lifecycle and cadence only; provider credentials remain outside this authority.

Retention and deletion append minimized tombstones in bounded, resumable batches of one to 100 records. Each cleanup attempt persists an exact replay receipt, including a zero-record completion, and pins the current retention or deletion authority and its cursor. Changing the authority starts a new checkpoint chain. A deletion request appends source-consent revocation in the same serializable operation, which blocks later imports and hides current evidence. Cancellation does not restore consent; an owner or administrator must grant it separately. The runtime role can call only guarded entry functions and has no direct table or projection-helper access.

## Released Part 9 Slice F — owner Learning Center travel experience

Migration `095_canonical_learning_center_travel.sql` extends the bounded Learning Center inventory with an explicit `sourceKind` so an identical tenant label can identify separate labor and travel authorities without collision. The inventory is capped at 100 sources and 50 service groups per source. The paid page composes the existing guarded travel source, consent, reconciliation, operation and calibration routes; it never reads a protected travel table directly.

Travel calibration renders route duration, distance, fuel or energy quantity and fuel cost independently and preserves canonical unavailable reasons. A newly consented source with no deletion request is safely presented as not deleted. Inventory, source and service loads carry separate local generations; stale completions are ignored so a slow prior refresh or source cannot overwrite the newest inventory and selected source. The isolated demo contains fictional labor and travel sources, disables mutation controls and never contributes to paid-tenant learning. Page entry resets restored scroll position, loading exposes `aria-busy`, reference tables carry captions and column scopes, and compact travel grids collapse at the narrow breakpoint.

## Part 10 Slice A — native equipment checkout-duration contract

Migration `096_canonical_native_equipment_utilization.sql` adds purpose consent and immutable native equipment checkout-duration observations. The baseline is the planned hours in one explicitly adopted Mission 24 equipment-cost plan and its exact underlying equipment plan. The actual is the sum of complete effective `check_out` to `check_in` intervals recorded by Mission 23 for each exact current reviewed native asset on the linked completed execution. `use` events are retained in the lineage and must occur inside a checkout interval, but they do not create a separate duration claim.

Every observation pins the estimate, adopted revision, both equipment plans, execution, completion, exact asset versions and every effective event revision and digest. A corrected event changes the live source digest, so prior advice becomes stale and its recommendation is masked. Consent revocation blocks new observations and hides derived history. The output remains advisory and cannot mutate an estimate, price, schedule, asset, allocation or policy. Checkout duration is not engine-on time, productive utilization, fuel burn, operating cost, maintenance cost, condition or availability. External utilization, cost, maintenance and downtime evidence begins in Slice B; those claims remain unavailable in Slice A.

## Released Part 10 Slice C — reviewed external asset reconciliation

Migration `098_canonical_external_asset_reconciliation.sql` records explicit owner or administrator links from current opaque job, vehicle and equipment references to a same-tenant canonical estimate or current active reviewed asset version of the matching category. Each immutable link or unlink revision pins the exact current source consent, all current active imported records carrying that typed reference, and the current target basis. Vehicle and equipment targets include the reviewed asset identity, asset version and current equipment-ledger revision and digest when present.

No name, manufacturer, model or reference similarity creates a link. Mixed vehicle and equipment references remain separate typed review items. A source correction or tombstone, consent change, target removal, category/version/review change or equipment-ledger change makes the saved link stale. Revocation hides the reference projection and blocks writes; re-granting consent cannot revive an earlier link. These links provide lineage only. They do not change a job, estimate, schedule, vehicle, equipment record, cost, allocation or policy, and they do not create a Slice D observation.

## Released Part 10 Slice D — imported utilization and operating-cost observations

Migration `099_canonical_imported_asset_outcomes.sql` requires separate purpose consent before one reviewed external job can be compared with its exact adopted equipment and equipment-cost plans. Complete current job and asset reconciliations, current asset versions and equipment-ledger bases, normalized records, units, currency and deterministic calculation version are retained in immutable lineage.

The utilization dimension compares only recorded machine hours with planned equipment hours. Engine hours, mileage, kilometres, cycles and job counts remain unavailable because this package has no authority to convert them. The operating-cost dimension compares only current job operating evidence in the adopted plan currency with the plan's operating-cost component; no exchange rate or unrelated ownership charge is inferred. Each dimension remains independently available or unavailable and requires exact set equality between distinct reconciled target assets and adopted plan assets. Missing or extra targets and multiple external references linked to one target fail closed for that dimension. Source corrections, tombstones, plan or match changes, asset or ledger changes and consent changes stale and mask earlier advice. The package adds no rendered interface and no automatic operational mutation. Maintenance events, downtime, condition and availability remain outside Slice D.

## Released Part 10 Slice E — maintenance, downtime, condition and availability

Migration `100_canonical_imported_asset_health_outcomes.sql` consumes only current Slice B maintenance and downtime records after a current Slice C reviewed vehicle or equipment match and a separate Slice E learning consent. It pins current source permission, the complete current typed-reference source manifest, match revision and digest, current target asset version and equipment-ledger basis, every current health record, deterministic calculation version and request identity.

Maintenance and downtime are separate dimensions. Recorded status counts are factual summaries. Downtime duration is summarized only when current periods do not overlap. There is no source claim for current condition and no complete observation-window denominator for availability, so both remain explicitly unavailable. Corrections, tombstones, source or learning consent, match, asset-version and ledger changes invalidate prior advice. No provider credential, fuzzy reconciliation, automatic mutation, calibration or rendered surface is introduced.

Source corrections, tombstones, match, plan, asset, ledger or consent changes make saved advice stale and mask its multiplier.
