# Mission 26 Part 10B — monthly KPI coherence gate

Status: implementation candidate. Migration 253, the guarded paid route and the shared paid/fictional-demo Command Center now mount the exact same-run monthly KPI boundary. No monthly KPI number, graph point, run or source reader is issued because the repository still lacks the Part 11-owned immutable multi-target run manifest and the required source authorities.

## Mounted guarded boundary

`canonical_forecast_monthly_kpis_v1_read` is owner/admin and tenant guarded and anchors the request to the current Part 10A demand origin. It returns one exact monthly window, the authenticated anchor identity and six ordered slot contracts. The run, manifest and every slot value/digest remain null. Revenue, demand, margin and role-capacity retain their Part 3 target versions; operating cost and profit are marked as derived display metrics that are not registered targets. Each slot declares its own unit, source scope and dimension requirement rather than borrowing the demand anchor's contract.

The public route accepts only that strict value-free contract. A stale or corrected baseline clears the anchor, month and bundle digest. The shared Command Center renders six compact cards and a graph boundary, but shows `Not available` for every value and graph point. Paid workspaces call only the guarded paid route; the isolated demo constructs the same value-free product state locally and is explicitly fictional. Loading, permission loss, stale currentness, errors, reset/expiry and recovery clear all prior values and identities.

This slice does not create Part 11 storage, a multi-target run, revenue-recognition policy, cost-basis policy or tenant-wide capacity aggregation. A later additive contract may expose partial valid slots only when one authenticated manifest explicitly identifies present and absent targets. Missing revenue or cost continues to withhold profit and margin. Authenticated observed zero remains a future supported value distinct from the current absent/unavailable state.

Part 10B calls for monthly revenue, operating cost, profit, margin, demand and capacity cards and graphs **from the same forecast run**. Today's `m26-forecast-output-v1` describes one target and one horizon; Part 3B's supplied comparison receipts and Part 10A's projection cannot prove a complete, authorized multi-target run. Mission 26 Part 11B has not yet supplied the immutable run inventory and bundle identity needed to claim that six separately produced values belong to one run. A matching month or snapshot digest alone is insufficient: the values could use different cutoffs, target versions, corrections, policies or source populations.

## Required display relationship

An eventual saved run must own a bounded manifest of target outputs for one tenant and prediction cutoff. Each card and each graph point must reference that run identity, its versioned target, exact half-open monthly reporting window, business time zone and calendar basis, unit/currency, calculation version, source snapshot and coverage receipt, current correction status, and applicability. The manifest must identify absent targets explicitly. A chart may contain multiple months, but each point must retain its own run identity; a current-versus-prior comparison uses Part 10A's separate comparability gate. A card must not quietly select a newer revenue output and an older cost output to manufacture profit.

| Display slot | Existing target/authority | Gate before a number |
| --- | --- | --- |
| Revenue | `revenue.earned_value.v1` is cataloged in Part 3A. Part 6C records that an approved earned-revenue recognition basis is unowned. | An authorized period reader, recognition policy, complete event-time coverage and a compatible run. Never subtract mismatched amounts. |

The eventual bundle validator must require shared tenant, saved-run identity, prediction cutoff and monthly reporting window, including its calendar basis. It must validate each slot against **its own** versioned target, unit, dimension and applicability contract: demand is a count, margin is a ratio, and capacity is role-scoped hours, so these fields cannot be required to match across all six slots. Financial operands used together for cost, profit or margin must have compatible currency, recognition and cost basis. An invalid or missing component withholds dependent profit/margin while unrelated valid slots may remain independently available **only** when the owning run and UI explain that partial coverage. Forecast ranges retain Part 9's deterministic-versus-calibrated distinction. Source failure, correction, revocation or deletion must flow through Part 11C invalidation and visibly retire affected card and chart points without rewriting historical runs.

## Current safe experience and acceptance

The paid and synthetic demo Command Center may explain that the monthly forecast is unavailable until the required evidence and run exist. It must not render zero placeholders, fabricated graphs, default profit, or a generic confidence percentage. A static live dashboard KPI is not a forecast merely because its label says “forecast.” The earlier Part 6D revenue-wording boundary and Part 7E missing-overhead gate apply here.

Numerical-path acceptance remains contingent on an authenticated same-run manifest and source readers. That later path must cover source-complete positive and observed-zero months; partial and conflicting coverage; one long job allocated over multiple months; corrected/revoked records; incompatible currency/calendar/cutoff/target versions; double-cost prevention; zero revenue; role-specific capacity; and current-versus-prior comparisons. The current value-free path instead proves strict absent-target handling, tenant/role/provider isolation, stale clearing, correction/recovery, zero-versus-unavailable separation, and plain-language responsive paid/demo cards and graph boundary. Independent exact-head audit is still required. CI, provider, private-production and physical-device evidence remain separately reported as available or unavailable. This document does not reopen released Mission 24 or Mission 25 contracts and does not invent a recognition or aggregation policy.
