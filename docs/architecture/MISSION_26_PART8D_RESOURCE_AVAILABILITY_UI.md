# Mission 26 Part 8D — resource-risk outlook implementation candidate

The existing paid and isolated-demo Command Center now uses one compact Resource outlook beside Demand outlook. The paid surface reads the released, owner-scoped Part 8A material-demand, Part 8B asset-utilization and Part 8C route-load endpoints. The demo runs the same validator and renderer with local fictional contract-shaped positions and never calls a paid route. No additional dashboard or parallel calculation was introduced.

Each domain validates its complete response contract before rendering. The native evidence disclosure exposes the current authenticated tenant and role; checked-at and source-as-of times; horizon, business time zone, source-coverage counts, complete-as-of and pagination state; evidence and calculation digests; booking, assignment, estimate and composition identities; and the exact domain source lineage. Material quantities retain material identity, unit, planned window, component-line and material-plan lineage. Claimed asset hours retain asset, meter, reset/correction, service-threshold, readiness, equipment-plan and exact planning lineage. Declared route distance retains trip identity, route direction, return-leg, movement/resource boundaries, distance unit and exact travel-plan lineage. The graph shows separate record counts only when issued domains share one business horizon; it never adds quantities, hours and distance or combines incompatible units.

The outlook clears all older values and prior tenant/role context before every load and clears each rejected or failed domain independently. A complete response renders Current, one or two valid domains render Partial, and no issued domain renders Unavailable. A legitimate authenticated `state: unavailable` response retains its exact validated reason, coverage state and relevant evidence in the disclosure while issuing no value or graph point. Workspace withdrawal clears every card, graph and drilldown before recovery. Paid and fictional demo therefore share loading, correction, failure and recovery behavior while their data and providers remain isolated.

Released evidence boundaries remain visible. Demand is not inventory or a receipt. Claimed planned hours are not actual meter time or checkout duration. A service-threshold position is not a verified service date. Declared vehicle-leg distance is not verified road mileage, and road travel remains distinct from onsite equipment movement. The surface does not issue a shortage, reorder time, stockout or purchasing risk, maintenance date, downtime risk, verified mileage, route timing, fuel or energy use, capacity risk, probability, recommendation or automatic action when the corresponding released output says unavailable. Unavailable values render as `Not available`; zero is retained only when an authenticated issued value is exactly zero.

The candidate includes keyboard-focusable native details, live status updates, labelled graph semantics, mobile card reflow, restrained light/dark styling and stale-value recovery. Automated browser evidence can verify those mechanics. Physical Safari, real provider evidence, private-production data and founder visual approval remain separately unavailable; Playwright WebKit is not physical Safari and does not grant the founder's visual verdict.

This document records the implementation candidate for one independent exact-head whole Part 8 audit. It does not itself accept or release Part 8.
