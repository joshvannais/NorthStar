## Reproducible source and evidence

Run `tests/browser/m23-part12-acceptance.js --browser=chrome --output=NEW_PATH`
and separately with `--browser=webkit`. Each output must be a new directory.
Use the existing `M19_PG_ADMIN_URL`, `M19_EXPECTED_PG_DATA_DIR`,
`M19_EXPECTED_PG_PORT`, and `M19_TEST_RUN_ID` disposable-server identity gates.
They require loopback, the exact expected data directory and a non-5432 port.
The run asserts PostgreSQL 18.x, UTF8, UTC, locale C and checksums enabled.
Distinct nonsuperuser migration-owner and runtime roles are provisioned and
removed with the disposable suite database. The shared fixture's default behavior
is preserved; only the new opt-in path stops after real scheduling approvals.

Each browser run provisions one synthetic job and retains its single appointment,
assignment and execution IDs across all stages and viewport revisits. Separate
browser runs use separate disposable databases and naturally different UUIDs.
No route response is fulfilled by an interception or replaced with canned data.
Browser network interception only blocks external destinations and records
ordinary POST bodies. Provider transport is prohibited, not activated.

Only synthetic accounts, tenant/profile/workforce skill/location, lead graph and
explicitly labelled synthetic reviewed equipment research are seeded using the
fixture owner. Availability declarations, assignment/dispatch previews and
approvals, asset draft confirmation, and every operational action use mounted
production HTTP with ordinary durable sessions and CSRF. No assignment trigger
is disabled on this path. No availability, skill, research, physical stock,
qualification, safety or legal fact about an actual person or business is claimed.
