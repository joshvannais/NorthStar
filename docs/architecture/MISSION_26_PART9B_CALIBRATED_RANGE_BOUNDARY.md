# Mission 26 Part 9B — calibrated range boundary

Part 9B may eventually issue probability ranges only after a complete, authorized set of predictions made **before** their outcomes and sufficiently comparable finalized actuals have been independently evaluated. The repository does not have that evidence today. Part 3C's `evaluationGates` intentionally returns `sampleSufficiency: unavailable` and `calibration: unavailable`, even if a synthetic fixture contains interval hits. Part 9A's reproducible arithmetic candidate is not a saved production prediction. The forecast-output v1 shape can carry a `calibrated_interval` label and backtest digest but has no nominal coverage level or quantile definition. Shape acceptance alone cannot authorize that label.

## Required identity before a range can be issued

An additive, versioned interval policy and evaluated run must pin the tenant, target and definition, unit/currency, horizon and grain, service/area/dimension scope, source snapshot and feature definitions, algorithm/build and parameters, training and held-out origin periods, outcome-finality policy, nominal interval coverage, quantile definition, evaluation policy and complete eligible-origin inventory. P10/P50/P90 must mean the tenth, fiftieth and ninetieth percentiles of the **same named outcome** under one applicable population and horizon. They are not favorable/base/adverse method assumptions. P10–P90 is a nominal central 80% interval under the reviewed quantile policy; empirically calibrated 80% coverage must not be claimed until held-out evaluation supports it. Their ordering and unit must be checked with exact decimal arithmetic; a forecast amount of zero is valid only with source evidence, while a missing amount remains unavailable.

The complete origin denominator includes forecasts that were unavailable, unpaired, later corrected or revoked, and normalization failures. A saved prediction cannot be generated after its outcome and then backdated. Evaluation must compare the pinned model on held-out rolling origins against actuals that became final later, report pair count and exclusions, empirical coverage against the declared nominal level, quantile-specific error or scoring, recency, drift and material downside. A contractor-specific policy must set sufficiency, independence/concentration and acceptable error thresholds for the decision and target; this document sets no universal sample count or automatic pass. A small or biased history, source loss, scope shift, changed algorithm, stale evaluation, missing policy, or weak interval coverage returns a named unavailable state. Another tenant's history cannot silently fill a gap.

Part 3B's comparator and Part 3C's descriptive counts can be reused but do not prove inventory completeness or calibration. Part 3D's static candidate catalog does not activate an algorithm. A future guarded source/run reader must authenticate the exact source snapshot, tenant, current purpose/retention, approved algorithm and policy, complete saved-run inventory and later actual receipts; Part 11B/C must retain immutable run/evaluation revisions and invalidate current displays after correction or revocation. Existing output v1 remains unchanged. Any production quantile contract is additive and independently reviewed for policy identity, nominal level, quantile semantics and compatibility; it must not reinterpret a previously issued v1 range.

## Mounted unavailable boundary

Migration 249 and `GET /api/v1/forecast/calibrated-ranges/:originId` implement the smallest guarded runtime behavior that current evidence supports. The owner/admin reader first authenticates the exact current Part 9A baseline, including its target, source scope, profile/calendar, horizon, unit, immutable algorithm definition/build, source receipt and deterministic digests. It then returns a value-free `m26-calibrated-range-assessment-v1` result. The response names every missing prerequisite and leaves all counts, policy identities, nominal coverage, empirical coverage, quantile scores, P10/P50/P90 values, distribution parameters and backtest digests null. It distinguishes the incompatible point-only Part 3 evaluation target from the requested Retell demand target rather than borrowing those descriptive results.

The complete eligible-origin denominator is explicitly defined to include issued, unavailable, unpaired, corrected, revoked and normalization-failed origins. Its counts and digest remain unavailable because no authenticated complete inventory exists for this target. The same is true for pre-outcome chronology, comparable finalized outcomes, a contractor-reviewed sufficiency/independence/concentration/error policy, a versioned quantile policy, and held-out evaluation of recency, drift and material downside. A current deterministic baseline produces a reproducible assessment digest, not a backtest or calibration digest. Source/profile correction or revocation clears the baseline identity and assessment digest; a newly authenticated origin yields a new assessment identity while still withholding the statistical claim.

The route has no paid/demo UI mount, stores no run or evaluation, does not reinterpret output v1, and cannot issue a probability distribution or range. Part 11 retains general run/evaluation storage and correction lifecycle ownership. Runtime reconciliation grants only the guarded reader and withholds the helper from both PUBLIC and the runtime role. Independent whole exact-head audit and normal release remain required before final Part 9B acceptance.

Future numeric acceptance still must replay a fixed complete set of prior-as-of predictions against later finalized actuals, including zero, missing, outlier, correction, changed calendar, narrow subgroup and source withdrawal cases. It must test noncrossing quantiles, unit/currency matching, nominal-versus-observed interval coverage, sample concentration, deterministic scenario separation, tenant/demo isolation and failed source/policy recovery. An independent audit must verify the exact policy, denominator, temporal cutoffs and calibration decision before any real probability label can appear.
