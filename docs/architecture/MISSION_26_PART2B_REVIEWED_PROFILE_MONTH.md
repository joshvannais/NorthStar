# Mission 26 Part 2B: reviewed Business Profile month claim

Status: isolated, unreleased bounded implementation candidate. Full Part 2B remains open.

The paid owner/admin `GET` and `POST /api/v1/forecast/reporting-windows/month-attestations` endpoints let an authorized person record that a specific canonical Business Profile revision described one completed local calendar month, or revoke that claim. The owner supplies an explicit reason, confirmation version, profile identity and hash, expected revision and digest, and idempotency key. A tenant-scoped, immutable revision chain records actor, membership, authenticated session, time, request digest and previous receipt. The capture function checks current authorization and CSRF inside the database transaction. Replays return the original receipt; stale revisions and request-key conflicts fail closed. The runtime role can execute guarded functions but cannot read or mutate the table directly.

The confirmation pins both the normalized Business Profile hash and a private digest of the raw profile, including calendar fields. A later raw-profile change invalidates `profilePinVerified` even if it leaves the normalized hash unchanged. Revocation remains possible after a source correction. The raw profile and its private digest are not returned by the API.

This is **owner testimony about historical applicability**, not independently verified historical calendar evidence. A current profile revision, even with an owner claim, cannot prove prior operating hours, holidays, service areas or observation completeness. Both endpoints explicitly return `historicalCalendarVerified: false`, `observationCoverageVerified: false` and `forecastIssued: false`; no feature, forecast, revenue baseline or saved run consumes the claim. A later source reader must reconcile the claim against actual version history and complete, comparable observations. No paying customer or recovered Retell history is required to implement or test this bounded mechanism; live-data validation remains separate.

Mounted disposable-PostgreSQL tests use fictional tenants to cover confirm, replay, stale-write rejection, revocation, malformed/future requests, actor and tenant isolation, CSRF, runtime-table denial, normalized-hash corruption, raw-calendar change and continuing forecast withholding. CI, production, provider, physical-device and live-history evidence are not claimed.
