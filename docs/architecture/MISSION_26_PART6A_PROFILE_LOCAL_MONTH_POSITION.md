# Mission 26 Parts 6A and 2B: current-profile local-month price position

Status: isolated, unreleased bounded integration candidate. Neither frozen slice is complete.

The paid owner/admin `GET /api/v1/forecast/price-history/ordered-snapshots/:snapshotId/profile-month-candidate?localStartDate=YYYY-MM-01&currency=USD` route combines the existing ordered Mission 24 approved-price receipt with a company-local monthly window derived from the active Business Profile. Currency is optional. Account, tenant and forecast-read gates precede the read. The route recomputes the profile normalization hash and pins the profile ID, version, hash, IANA time zone, local dates and derived UTC bounds in the returned window. It exposes no raw profile, event list or private source-order identifiers. Both source reads occur inside one guarded transaction; the receipt's tenant source-order lock is held until commit.

The arithmetic reuses the pure ordered-price candidate evaluator. Its event instants are compared with the local month's UTC bounds at microsecond precision, including months that change daylight-saving offset. It retains source-order, pre-anchor lineage, stale-receipt, currency and amount-capacity checks. The reusable evaluator also rejects a reporting window whose organization differs from the ordered receipt's organization, independent of route authentication. The older UTC-month endpoint is preserved.

`profileBasis: current_active_profile_at_read` is an essential limitation: today's Business Profile does not prove the same calendar applied in the historical month. The response explicitly leaves `historicalCalendarVerified`, `observationCoverageVerified`, `sourceMonthVerified`, `calendarPeriodVerified`, `eligibleForForecast`, `wholeBusinessCoverageVerified` and `forecastIssued` false. An earlier-than-anchor month remains unavailable even if its observed event count would be zero. A passing bounded source check would authenticate only the canonical NorthStar price-decision window as of receipt capture, not booked work, earned revenue, off-platform prices or an eligible future forecast.

Pure tests cover a New York daylight-saving transition and events on opposite sides of the local boundary. Mounted disposable-PostgreSQL tests cover the paid route, active profile pins, unavailable pre-anchor month, malformed queries, denied member and cross-tenant reads, private response minimization, and unchanged UTC endpoint behavior. This does not supply historical profile validity, whole-business observation coverage, enough comparable months, a saved forecast run, or final Part 6A/2B acceptance. CI, provider, private production, physical-device and live-data evidence are not claimed.
